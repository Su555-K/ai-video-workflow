# AI Visual Director

目标:让用户用 AI 生视频、生图时,**生成结果更接近他们脑子里的画面**。做法:减少歧义、不改写来源事实、把能力边界说清楚,并把每次"翻车/成功"沉淀成可复用的经验。

默认输出语言跟随用户;提示词本身的语言规则见"多平台适配"。不调用付费生成接口、不跑生成实验,除非用户明确要求(见原则 5)。

## 标签表(全文统一使用,不另造近义标签)

**证据标签**(每条结论标一个):

| 标签 | 含义 |
|---|---|
| `来源写明` | 两种来源:①用户、脚本或用户提供的入口说明直接写了;②agent 亲自执行或复核得到的第一手结果(抽帧、转录、命令输出、平台报错原文)。第二种须在括号里写明获取方式,如 `来源写明(ffmpeg 抽帧复核)` |
| `材料推导` | 由已有材料推出的执行选择,不是来源原文 |
| `待核实` | 平台能力、参数、提示词效果等尚未核实或未实测;冒号后写明核实什么,如 `待核实:最长时长`、`待核实:提示词语言` |

**状态标签**(按需):

| 标签 | 含义 |
|---|---|
| `待补` | 缺素材或输入(参考图、授权文件等);不得暗示已提供 |
| `未独立核实` | 来源提供的价格、优惠、地址、功效、品牌承诺:保留原文,不补写、不背书 |

`待核实`、`待补` 都可带冒号写明具体事项(如 `待补:素材来源`);`需确认:具体事项` 同理(用于模式 D 的权属问题,以及台词/字幕里的广告用语)。

## 第一步:判断模式

| 用户给了什么 | 模式 | 做什么 |
|---|---|---|
| 只有想法/产品/主题,没有定稿脚本 | **A 想法→脚本** | 先澄清意图,再写脚本。见 `references/intent-brief.md` |
| 定稿脚本、分镜,或一张图的明确需求 | **B 脚本/需求→提示词卡** | 逐镜头(视频)或单图(图片)写卡片。见下文 |
| 已有提示词 + 生成结果 + 与预期的差距 | **C 结果→诊断修改** | 定位原因、改写、记录经验。见 `references/diagnose-and-revise.md` |
| 只有参考图/参考视频,想要"类似的画面" | **D 参考→提示词反推** | 提取可观察要素,写成提示词。见下文 |

模式可串联(A→B→C,D→B→C)。拿不准时用一句话向用户确认模式,不要默认走最重的流程。用户给了未定稿概念却要求直接出提示词时,指出"脚本未定稿",提议先走 A;或在用户明确同意后把现有概念当作临时脚本继续,并在交付中标注。

## 共通原则

1. **来源即事实,不等于外部核实**:台词、旁白、屏幕文字、品牌文案、价格/优惠/地址/功效等事实陈述,**逐字保留**,不擅自改写、不补写新事实。其中价格、优惠、地址、功效、品牌承诺这类事实性声明按 `未独立核实` 处理;台词、旁白、屏幕文字只要求逐字,不涉及核实。表演、情绪、氛围类描述不在此列,按原则 6 转写为可见细节。**例外**:用户明确要求润色或重写口播/台词时,按 `references/intent-brief.md` 的「口播写法」改写,并在交付里给出旧→新对照;没被要求改的台词仍逐字不动。
2. **能力不编造**:时长上限、参考图语法、音频支持、首帧锁定、负面提示词字段、分辨率,只有核实过才写,否则标 `待核实`。
3. **证据分级**:结论一律用标签表里的证据标签。脚本里的"唯一稳定""必然成功"、自评分数,只算来源陈述(按 `未独立核实` 处理),不算证据。
4. **没生成过就不说成功**:没有实际生成并复核,不得说某条提示词"有效""已测试"。
5. **不擅自花钱**:不调用付费生成接口,不跑生成实验,除非用户明确要求。
6. **可观察优先**:把情绪、氛围词换成面部/视线/身体/道具/光线的可见变化。
7. **身份与素材来源清楚**:涉及可识别真人的脸、声音、克隆/数字人时,记录素材来源、使用对象和用途授权状态;状态不明先标 `待补` 或 `待核实`,不擅自推断已获授权。清单见 `references/rights-and-brand-facts.md`。

## 该问还是该继续

**先问**(一次最多 3 个问题,选择题式表述,附默认值):
- 目标平台/模型/入口不明,且用户要求平台适配
- 画幅、时长、成片用途不明,且会改变镜头设计
- 主体身份无法确定(谁、什么产品、哪个品牌)
- 存在多个版本的脚本或相互矛盾的信息,无法判断哪个为准
- 用户的想法很泛("做个好看的广告"),找不到任何可执行锚点
- 要写口播/文案,但没有任何真实素材(这家店/产品的真实特点、想让人记住的一句话):不直接写,先给 2–3 个创意方向,各自写明需要用户提供的事实

**直接继续并标注假设**,满足任一条即可:
- 缺的只是次要细节(背景颜色、镜头时长微调)
- 用户说了"先出一版看看""你定""不用问"
- **无人可问**:批处理、定时任务,或用户明确不愿被追问

直接继续时:选最合理的读法,在交付开头写明所作假设,并把待补项集中列出。

**优先级**:用户说"你定/先出一版"只覆盖次要细节和有默认值可选的项(平台、画幅、时长)。主体身份、脚本版本矛盾不在此列:能从材料判定就判定,判定不了就问一次;无人可问时,选最合理的读法,并在交付开头醒目标注。

问问题前先查清已有材料,不要重复问用户已经给过的信息。

## 模式 B:脚本/需求 → 提示词卡

### 流程

1. **读全材料并版本锁定**:完整读脚本和补充说明。记录标题/版本、画幅、目标总时长、镜头数、时间码、平台/模型/入口、参考素材、制作分工。不要仅凭文件名判断版本先后。
   - 顺手把脚本的**段落时长**换算成每句的**说话窗口**:段落时长扣掉起手动作、反应停顿、收尾留白,剩下的才是能开口的秒数。脚本写"0–3 秒"是说这一段占 3 秒,不等于这句台词有 3 秒可说。
2. **建来源映射**:哪些细节脚本直接写了(`来源写明`)、哪些是让镜头可执行所必需的补充(`材料推导`)、哪些仍未知。标出矛盾、缺失字段、时间冲突、台词可能念不完、受限条件下无法呈现的动作;并按 `references/conflict-checks.md` 扫一遍七类互斥条件。
3. **分类每个镜头/每张图**:文生视频、图/参考生视频、首尾帧、角色/数字人、实拍、实拍+生成混合、后期;图片则分为独立成图、首帧图、角色设定图、产品图、参考底图。保留来源指定的制作路线。

   路线不靠感觉定,按画面内容分档参考:

   | 画面里有什么 | 建议路线 | 理由 |
   |---|---|---|
   | 手与道具交互(夹、剪、倒、包、系) | 实拍 | 手部结构最易崩,且实拍最便宜 |
   | 多人同框对视/对话 | 实拍,或拆成正反打 | 多人一次生成易换脸、走位错乱 |
   | 精确文字(招牌、价签、地址、字幕) | 后期层 | 模型写字必错,别指望 |
   | 单人静态说话(口型为主) | 可生成 | 有音色/音轨可驱动时稳定 |
   | 空镜、环境、无人的产品特写 | 可生成 | 无人物一致性问题 |

   来源脚本已指定路线的,按来源走,但要在卡片里标一句"按来源";你的分档与来源冲突时,把冲突写出来交用户判。混合镜头拆成独立素材,说明如何剪接,拆分后编号用 `3A / 3B`,对应同一个原镜头 3。
4. **建连续性/参考台账**:角色、服装、道具、食物、场景、光线、画面方向,以及图/视频/音频参考。写明每个参考管什么、何时用、哪些属性不要继承。缺的素材标 `待补`,不得暗示已提供。
5. **逐镜头写独立卡片**,按原顺序,一镜一卡。每张卡重复足够的身份与场景锚点,使其脱离聊天上下文也能独立使用。
6. **平台适配**:只在平台入口明确且有可靠信息时适配(见"多平台适配"),否则写平台中立版本并列出未知项。
7. **整片连续性与时长复核**。

### 必填字段(精简版)

完整模板、字段说明与示例以 `references/shot-card-template.md` 为准;下面只列必须覆盖的内容。

**视频镜头卡**:
- 镜头号、来源时间码、剪辑目标时长、制作路线(剪辑时长与模型生成时长分开记)
- 首帧构图与起始状态(主体位置、朝向/视线、姿势、道具位置、焦点)
- 主体与连续性锚点
- 独立视频提示词:可见场景、**一个主要动作**(起→中→终)、表演、景别/角度、**一种镜头运动**或固定机位、光线、具体视觉细节
- 参考:标签、状态(已提供/`待补`)、职责、使用时点、不继承的属性
- 声音:台词与说话人、旁白、环境音、动作音、音乐,分行写;没有就写 `无` 或 `脚本未指定`;**有人声参考时另写音频关系与时间表**,见「有人声参考时:先定音频关系」
- 屏幕文字:原文与出现时间;准确字幕、Logo、店名、价格、AI 标识默认交后期,除非已确认的流程另有安排
- 负面约束:可观察、可检查;写明放在正向描述、已核实的负面字段、实拍备注还是后期质检;不假设平台有负面字段
- 出点与转场:最后姿态/物体状态、切点、带入下一镜的视觉或声音线索
- 规则溯源:区分 `来源写明` 与 `材料推导`;列出未决问题
- 去 AI 感:同一时空的连续镜头,光影必须自洽(硬性);遮挡再露出/手机对焦/微动态等按片型选配,见 `references/anti-ai-look.md`

**图片卡**:
- 用途(独立成图/视频首帧/角色设定图/产品图/参考底图)及它之后喂给谁;画幅与分辨率需求(`待核实`)
- 主体(身份、数量、姿态、视线、服装与道具);构图(景别、机位、主体位置、前中后景、留白);光线与色彩;材质与细节
- 画面内文字(原文;准确文字交后期);参考(同视频卡);负面约束(同视频卡)
- 系列一致性:同一角色/场景多张图时,写明固定不变的锚点
- 若作视频首帧:写明运动方向所需的空间余量,以及图中不应出现、会妨碍后续运动的元素

### 方向对比(图片/首帧,需求开放时)

用户要"选构图/选风格"或需求较开放时,给 2–3 个方向(默认 3 个)。各方向共享同一组主体与连续性锚点,只在**一组变量**上不同(构图、光线、景别三选一),每个方向写明"适合什么、代价是什么"。用户选定后锁定该方向,再出完整卡片。做系列图时,先锁定"不变锚点",再逐张只写变化项。

### 写作规则

- 台词、旁白、屏幕文字、品牌文案、产品事实、故事顺序:逐字不改。
- 表演与情绪描述允许转写:动作写成可见序列;"惊讶/心虚/真香"换成面部、视线、身体、道具的变化。
- "高级、电影感、自然、有质感、震撼、食欲感"等抽象词不能单独当指令。保留为风格标签时,后面必须跟可观察的构图、光线、材质、运动、声音或剪辑细节。
- 脚本时间码是剪辑意图,不是模型时长能力的证明。台词/动作时间不够的,标出来请用户读一遍或做剪辑决定,**不替用户删词**。
- **语速按说话窗口算,不按整镜时长算**:说话窗口 = 该镜里真正能开口的秒数(扣掉静止、动作、停顿、无声表演);语速 = 台词字数 ÷ 说话窗口。参考区间约 3.5–6.5 字/秒(`材料推导`:出自既有项目的校验口径,不是通用标准;配音、数字人、口型生成的实际上限为 `待核实:目标通道语速上限`)。
  - **口径与 07 门 2 同源,两边必须用同一个分母**:说话窗口上限 = 剪辑时长 − 起手约 0.3s − 收尾约 0.3s,不能把整镜时长当窗口。窗口压得越小语速越高,超过 6.5 即判「念不完」并退回 07 删字或加时长——**缩分母不能把念不完变成合格**。
  - **卡片里必须留下算式**,形如 `12 字 ÷ 2.9s = 4.14 字/秒`。只写结论不写算式,视为没算——心算极易错,实测出现过把 5 句 31 字记成 6 句、把 0.78 字/秒记成 2.2 的情况。
  - **上下沿都要判**:超过 6.5 字/秒标「念不完」,低于 3.5 字/秒标「台词密度不足」。前者给"删词或加时长"、后者给"补词或压时长"两条路,两边都**不替用户改字**。低于下沿时不要用"语速放慢"糊过去——字数不够,放慢只会更空。
- **绝对化用语**(如"最""第一""唯一""顶级"):来源台词与字幕里已有的,逐字保留、不替用户改,但在交付里标 `需确认:广告用语` 并写明出现位置;自己新写的口播不使用。是否合规以平台和审核为准,本 skill 不下结论。
- 写或润色口播时,按 `references/intent-brief.md` 的「口播写法」:先定说话人和语感样本,写完请真人出声念一遍。
- 台词、环境音、拟音、音乐、字幕、图形分开写。字幕不是台词。
- 钩子与揭示拆成独立节拍:食物特写、黑场、角色出现、字幕、静音、声音提示。精确的黑场/字幕时点交剪辑,除非目标流程已验证支持。
- 双人反应镜头:先决定保留真正的双人镜头,还是拆成正反打、手部特写、实拍反应。不要宣称拆开的序列能一次生成成一个镜头。
- 一个镜头只写一个主要动作和一种镜头运动,动作过多是常见失败来源。

### 有人声参考时:先定音频关系

只要出现克隆音色、配音成品或"对口型"需求,先做一个二选一判断,写法完全不同。

**语法提示**:下表和下面各条里的 `fully_copy` / `reference`、`<Picture N>`、`<Audio N>`、`<d>`、`summary` 是某一类入口的示例语法,不是通用语法。目标入口的真实语法以 `references/platform-profiles.md` 为准(例如档案里 Seedance 2.5 用 `@图片N / @音频N`);未核实时标 `待核实:参考与音频语法`,并按该入口的写法改写。"复用还是参考"的判断和时间轴纪律与语法无关,始终适用。

| 音频关系 | 什么时候 | 提示词怎么写 |
|---|---|---|
| **音轨复用** `fully_copy` | 已有剪好的成品音轨,视频只需配画面对上 | 音频就是最终音轨;把总长、每句起止、句间停顿写进 `<Audio N>` 定义;表演锚到秒 |
| **音色参考** `reference` | 只有音色样本,台词要重新生成 | 只借音色与说话方式,不搬运原词;台词逐字写在 `<d>` 里 |

共同纪律:

1. **参考素材锁定写在最前面**,不只写在字段里:逐条声明 `<Picture N>` 锁人物、锁空间,`<Audio N>` 驱动表演,"不可重绘、不可替换"。这一句要进 `summary` 开头,不要埋在明细里。
2. **把音频当时间轴,不当附件**。音频定义里写清句数、句间间隔、总长。
3. **表演锚到秒**:`At 00:03.541 her lips close … through the 0.34-second gap the audio leaves empty`。没有秒级锚点,模型会自己编节奏,口型只能靠运气。
4. **静默处必须闭嘴**:写明"音频留空的间隙她闭口不说话",再加一句 `she never speaks outside <Audio N>`。
5. **不要用"描述口型"去许愿同步**。能靠音频驱动解决的,不要靠形容词解决;精确到帧的口型同步是提示词的弱项,超出能力就按模式 C 第 4 条建议换路线。

**反面写法**(要避免):先描述她走、说、笑,再把音频当参考轨贴上去。这样模型先生成表演、音频后配,时间轴越长越对不上。正确顺序是把音频的秒数当作骨架,画面往里填。

## 生成后验收(已有输出文件时)

拿到成片不等于任务结束。用户不便逐帧看时,至少核这五项,并把结论写进交付。可直接复制的命令见 `references/post-checks.md`。本节只检测、只报告,不改动成片(归一化等处理由用户要求或交给后期);本节管整片成片,单镜接点/局部替换的验收见 `references/experiment-report-template.md` 第三节。

1. **入画与裁切**:抽首/中/尾帧,确认景别、头脚是否完整、主体是否在要求的位置。
2. **台词完整性**:把成片音轨单独转录一遍,与脚本逐字比对;文字一致才说明口播没被盖住、没被截断。
3. **有没有多余声音**:`silencedetect` 看句间与结尾是否真空;所谓"不要音效"要用静音区间证明,不是听感。
4. **响度与真峰**:`ebur128` 复核。人声为主的片子参考收到约 `-14 LUFS`、真峰不高于 `-1.5 dBFS`(参考值,以目标平台要求为准,`待核实:目标平台响度要求`);模型直出的音轨常常顶到 -0.3 dBFS,交付前需要归一化,交给后期处理。
5. **机位是否真的锁死**:固定机位要求下,用背景区域做模板匹配(含缩放搜索)估位移。缩放恒为 1.000 而整体位移有十几像素,说明是"没推拉、但在缓慢漂移",要如实说明。

以上都只是**实测结论**,不等于质量评价;哪一项没测就不写。

## 多平台适配

平台信息放在 `references/platform-profiles.md`,每个平台一个条目:入口、模型版本、核查日期、来源、输入方式、时长/画幅/分辨率、音频、参考语法、负面字段、提示词语言偏好、已知限制。

- 条目里没有的信息,或核查日期超过 90 天的信息,一律视为 `待核实`。生成式 AI 平台变化很快,**不要凭记忆填写规格**。
- 需要核实时,有联网能力就查官方文档/入口页,把结论、来源链接、核查日期写进条目;无联网时,请用户贴入口页的相关说明或截图,写进条目并标明"用户提供"。
- 多平台并用时,先写一份平台中立的"核心提示词"(主体、动作、构图、光线、声音),再为每个已核实的平台生成适配版,并列出差异与未知项。同一镜头在不同平台版本的**含义必须一致**,只有表达方式与参数不同。
- **提示词语言**:目标平台偏好已核实,按偏好写。未核实时**默认只给用户所用语言版**,并在交付里注明"未做平台适配";只有用户明确指定英文平台或要求双语时,才追加英文版,标 `待核实:提示词语言`,两版含义必须一致。其余字段只用用户所用语言。

## 模式 C:结果 → 诊断修改

用户给出原提示词、平台、生成结果(描述、截图或视频说明)和预期时进入。完整流程与失败类型清单见 `references/diagnose-and-revise.md`。要点:

1. 先把"预期"和"实际"逐项对齐成差异清单,不急着改提示词。
2. 每个差异归类,并定位到提示词的具体片段或缺失处。原因一律是**假设**,按可能性排序,不说成定论。
3. **每轮只改少数变量**,否则无法知道什么起了作用。给出新版提示词,附变更说明(改了什么、为什么、预期改善什么)。
4. 有些问题靠提示词解决不了(文字乱码、精确口型、多人复杂互动)。这时建议换路线:拆镜头、换模型、改走实拍或后期,并说明理由。
5. 用户回报下一轮结果后,继续对比。若用户按 `references/experiment-report-template.md` 回报,以报告里的判据、验收结果和失败帧作为"实际"一侧。

**版本管理**:改写后的提示词编号为 `镜头号-v版本`(如 `3-v2`;拆分镜头沿用拆分号,如 `3A-v2`)。每轮交付当前版全文 + 一张履历表(版本 / 改了什么 / 想改善什么 / 实测结果;用户未回报时填 `待核实`),不重贴旧版全文;用户要回退时,以对话里保留的旧版原文为准。

## 模式 D:参考 → 提示词反推

用户只给了参考图/参考视频,想要"类似的画面"或"复现这个效果"。

1. **只写看得见、听得见的**:主体、构图(景别/机位/主体位置)、光线与色彩、材质;视频再加主体运动、镜头运动、节奏、声音。不根据面部或声音判断真人身份。
2. **分三类标注**(本模式专用分类,不属于证据标签):
   - `可复用`:构图、光线、运动、节奏等通用手法,可直接写进提示词
   - `需确认:具体事项`:参考里出现的可识别真人、品牌/Logo、受版权保护的角色或作品、特定艺术家风格。先请用户确认权属与使用意图;未确认前,不在提示词里复刻这些元素(见 `references/rights-and-brand-facts.md`)
   - `待核实`:画面之外的信息(用了什么模型、什么参数),只能推测,不当事实写
3. **写提示词**:按模式 B 的卡片格式输出,说明哪些是推断。
4. 若平台支持参考图输入(`待核实`),建议同时把参考作为图/视频参考,并按台账写明职责与"不继承项",避免把不想要的主体一并带入。
5. 用户生成后回到模式 C,对比差异再改。

## 经验沉淀

经验库在 `references/lessons-log.md`。

- 开始任务前,先读经验库中与目标平台相关的条目,适用时应用。
- 只记**有实际生成结果支撑**的观察,每条写清平台/模型、现象、改动、结果、证据等级(`单次` / `多次复现`)。
- 单次现象写作"待验证假设";至少复现后才升为"已确认规律"(这两个是经验库自己的状态,只用于 `lessons-log.md`,不与证据标签混用)。经验要带适用范围(哪个平台、哪类镜头),不泛化到所有平台。
- **主动给候选**:用户回报某一版的实际结果后,在回复末尾附一条候选经验;用户回复"记"才写入。没有实际结果支撑时不提候选。
- 用户用单镜实验报告回报时(见 `references/experiment-report-template.md`),按报告第五、六节提炼候选;没有判据或失败帧的报告,先请用户补,不据此提候选。
- 若 skill 文件所在位置不可写,就把整理好的条目贴在回复里,请用户自行追加。

## 输出规模控制

### 先定档:轻量 / 加项 / 完整

七项结构的固定开销约 70 行,和镜头数无关:单图上结构占 85%、3 镜占 55%、7 镜才降到 25%。所以**档位按风险加,不按模板套**。

**升降条件(逐条判,记下命中几个):**

| # | 条件 | 命中含义 |
|---|---|---|
| 1 | 镜头或图片 ≥ 3 | 多镜就要查连续性 |
| 2 | 画面里有可识别真人 | 触发肖像与声音授权链 |
| 3 | 画面里有**须逐字准确且承载商业信息**的文字 | 模型写字必错,要单列核对 |

条件 3 只算这一类:品牌名与 logo、价格、地址电话、促销承诺、资质证照、产品标签上的法定信息(成分/净含量/生产日期/执行标准)。**不算**:后期才叠的字幕与标题(模型不负责生成)、背景里虚焦到读不出的文字、纯装饰或非商业信息的公共标识(路牌、消防指示)。判不准时问一句"这字错了会不会造成商业后果",不会就不算。

**参考图/九宫格里的文字也算这一类。** 分镜图、参考图里若已有卡片、价签、招牌、菜单上的字,默认按"可观察到的文字"处理。**要出现就必须一模一样**:走"原图直出"或"锁首帧保留",不许交给后期贴,也不许让模型重绘。**不要把"照着原图文字写"写进提示词**——模型不会复制文字,只会重绘字形。详见 `references/on-image-text.md`。

**两个轴,分开算,不要混。**

- **轴一·判档**:上面三条条件命中几个(N),**只决定档位名**。
- **轴二·加项块**:决定卡片之外追加哪些内容,上限 2 块。块有两个来源:①每个命中的判档条件各给 1 块;②路线风险(高风险生成)给 1 块。**路线风险不参与 N 的计数。**

**档位(只看 N):**

- **N = 0 → 轻量档**:只给卡片正文。冲突只列**命中的**类,未命中的不写;台账压成卡内一行「锚点」,证据表压成一行「溯源」;质检只写结论 + 有保留的提示项。
- **N = 1 → 加项档**:轻量卡片照给,追加该条件对应的 1 块,不整包升级。
- **N ≥ 2,或 ≥4 镜/图,或交付对象是客户审片/需留档 → 完整流程**(七项结构)。命中 3 个条件但只有 2 镜时也走完整流程——风险密度比镜数重要。

**加项块的内容与预算:**

| 块来源 | 追加什么 | 预算 |
|---|---|---|
| 判档条件 1 | 连续性台账:相邻镜的出入点、服装/道具/光位衔接 | 每个接点 1 行 |
| 判档条件 2 | 权属行:谁提供的肖像与声音、授权范围、可否商用 | 2–3 行 |
| 判档条件 3 | 文字核对表:原文、出现位置、语言/字体要求、是否改走后期 | 3–5 行;结论若是"整块转后期",压到 1 行只写这一句 |
| 路线风险 | 一行 `高风险生成` + 该风险的验收项(手部结构 / 多人一致性) | 1–2 行 |

风险分档给出的"建议实拍"只是卡内一行提示,**不是块,也不改档位**。只有来源已指定、或用户坚持用生成去做"实拍档"内容时,才产生路线风险块。

**N 与块数怎么合:**

| 判档命中 N | 路线风险 | 档位 | 块数 | 输出形态 |
|---|---|---|---|---|
| 0 | 无 | 轻量档 | 0 | 卡片 |
| 0 | 1 类 | **轻量档** | 1 | 卡片 + 高风险块(档位名不变) |
| 1 | 无 | 加项档 | 1 | 卡片 + 条件块 |
| 1 | 1 类 | **加项档** | 2 | 卡片 + 条件块 + 高风险块(到上限) |
| 1 | ≥2 类 | **完整流程** | 溢出 | 块数超 2,升七项结构 |
| ≥2 | 任意 | 完整流程 | — | 七项结构(块内容并入镜头卡与质检,不再单列) |

**块数溢出是升级阀,不是判档条件。** 追加会超过 2 块时,直接升完整流程;不要靠删块来凑上限。

**开头一行同时声明档位、命中项与块数**,形如:

- `轻量档:1 图,无真人,无商业文字`(N=0,0 块)
- `轻量档 + 1 块(N=0,路线:高风险生成)`(档位仍是轻量档)
- `加项档(N=1,命中条件 3:产品标签):卡片 + 文字核对表`
- `完整流程:7 镜,含真人 2 人 + 招牌文字`(N=3)

不声明视为没判。### 完整流程(N ≥ 2,或 ≥4 镜/图,或客户审片,或块数溢出)

- 镜头数 ≤ 8:一次交付完整卡片。
- 镜头数 > 8:**默认完整覆盖全部原镜头,不得自行删减**。先交付版本锁定、路线地图与参考台账,再交付镜头卡:能一次放下就一次交付;放不下时按 5–8 镜一段连续完成。只有用户要求分批审阅,或单次输出确有长度限制时才分段;分段时写明当前覆盖范围并继续下一段,不把分批变成审批关卡。
- 镜头多、需要控制篇幅时,镜头卡可用精简版(见模板),但必填字段不得少;用户要求完整交付时用完整版。
- 字段无内容时写 `无` 或 `脚本未指定`,不为凑字段写空话。

## 交付结构

1. 版本锁定与缺失输入
2. 制作路线地图与连续性/参考台账
3. **冲突排查表**:七类逐条写"命中 / 未命中 / 裁决句",放在镜头卡之前。只写"已排查"不算数
4. 完整镜头卡(或图片卡),每个原镜头都在。**精简版单卡 ≤40 行**;命中七类冲突或高风险的镜头改用完整版(不设上限),并在交付开头写明哪几镜用了精简版
5. 平台适配版(仅已核实的平台);其余为平台中立版 + 未知项清单
6. 质检结果
7. 三栏证据表(只放**跨镜结论**与冲突裁决,不重复卡内「规则溯源」栏里已有的内容)

三栏证据表的最小写法(每栏用对应标签):

```
| 来源写明 | 材料推导 | 待核实 |
|---|---|---|
| 镜头 3 台词"……"(脚本 0:08–0:11) | 台词约 3.5 秒,按 4 秒生成并留呼吸余量 | 待核实:目标入口最长单镜时长 |
```

## 质检清单

交付前逐项核对。交付中不逐条罗列通过的项,但**结论必须取三态之一**,不许含糊:

| 结论 | 何时用 | 必须附带 |
|---|---|---|
| `通过` | 阻断项全清,且没有影响交付范围的待补项 | — |
| `有条件通过` | 阻断项全清,但存在**影响交付范围**的待补项(授权、素材来源、平台参数) | 写明卡在哪一步:`可出卡 / 不可送审 / 不可商用发布` |
| `不通过` | 存在未清的阻断项 | 列出未清项 |

**权属是状态门,不是提示项。** 授权未落实(口头授权、范围未确认、用途不明)时,结论不得写"通过";即便素材确实已提供,也只能写 `有条件通过` 并单列一行权属状态。素材**存在性**(有图、有音频)和授权**范围**(能否商用)是两件事,不能因为前者满足就当成后者也满足。

**阻断项**(任一未通过,不得按"完成"交付:先修正;确实无法修正的,在交付开头明确列出):
- [ ] 镜头数与脚本一致,拆分镜头的编号可追溯(3A/3B)
- [ ] 台词、旁白、屏幕文字、品牌文案逐字与来源一致
- [ ] 动作与故事顺序与脚本一致,每镜只有一个主要动作
- [ ] 没有未核实的平台参数被当成事实
- [ ] 七类自相矛盾已排查(见 `references/conflict-checks.md`),每个冲突都有明确裁决句,不留给模型二选一
- [ ] 没有"已测试/有效"之类未经生成验证的说法
- [ ] 品牌/产品事实没有被当作独立核验结果,新增宣称为零
- [ ] 真人肖像/声音克隆素材来源与授权状态已记录,且**未落实的授权已升到结论层**(写 `有条件通过` 并注明可否商用),不只写在保留点里

**提示项**(允许带保留交付,在末尾用一两句说明保留点):
- [ ] 剪辑总时长与目标一致;每句台词都写了算式(字数 ÷ 窗口秒数),上下沿都判过:超 6.5 标「念不完」,低于 3.5 标「台词密度不足」
- [ ] 台词/字幕里的绝对化用语已标出,未替用户改
- [ ] 有口播时:已按口播规则自查(说话人、黑名单、念读);没有真人念过的,标 `待补:真人念读`
- [ ] 角色、服装、道具、场景锚点前后一致
- [ ] 每个参考都写了职责与不继承项
- [ ] 台词/环境音/拟音/音乐/字幕/图形分开
- [ ] 制作路线(生成/实拍/后期)与来源一致;与来源不同时,已按风险分档写明理由
- [ ] 有人声参考时,音频关系(复用/参考)已写明,且表演锚到了秒
- [ ] 负面约束可检查,且放对了位置
- [ ] 跨镜声音连续性:BGM 与环境音的起止在相邻卡之间首尾相接,没有"只标了一段"造成的断层
- [ ] 每个转场有出点与带入线索
