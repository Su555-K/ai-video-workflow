# 09 · 提示词编译

> 把分镜翻译成模型能接的东西。**这一环不是「写得好」，是「不出错」。**

| | |
|---|---|
| **上一步给我什么** | **干净分镜表**（音画分离两张：画面 5 列 + 声音 6 列，共用一个镜号） |
| **这一步交什么** | 逐镜提示词卡（含验收点）+ 一句质检结论 |

### 输入端：拒收什么

**台词和画面混在同一张表里的分镜表，不接。**

| 收到什么 | 处理 |
|---|---|
| 画面表 + 音频表分离（干净分镜表） | ✅ 正常编译 |
| 单表但台词独立成列、且已声明"台词不进画面" | ⚠️ 可用，但要求先拆 |
| **台词和画面写在同一格** | ❌ **退回 07**，先做音画分离 |
| 只有一段总脚本，没有分镜 | ❌ 退回 07 |

**为什么硬**：混排的表喂进模型，模型会把台词画成字幕。这不是理论，是实测踩过的坑。

拆法见 [干净分镜表模板](../../05-学生包/模板/干净分镜表.md)。

## 四个模式，别用错

| 你手上有什么 | 模式 | 产出 |
|---|---|---|
| 只有想法/产品/主题 | **A 想法→脚本** | 先澄清意图，再写脚本 |
| 定稿脚本 | **B 脚本→提示词卡** | 逐镜头卡片 |
| 已有提示词 + 生成结果 + 落差 | **C 结果→诊断** | 差异清单 → 改写 |
| 只有参考图/视频 | **D 参考→反推** | 可观察要素 → 提示词 |

**模式可串**：A→B→C，D→B→C。

拿不准时它会问你一句。**不要默认走最重的流程。**

---

## 输出规模：三档，按风险加

这是这份 skill 最实用的设计——**不按模板套，按风险加**。

命中的条件越多，档位越高：

| 条件 | 含义 |
|---|---|
| 镜头 ≥ 3 | 要查连续性 |
| 有可识别真人 | 触发肖像与声音授权链 |
| 有须逐字准确的商业文字 | 模型写字必错，要单列核对 |

```
N = 0  → 轻量档：只给卡片正文
N = 1  → 加项档：卡片 + 1 个块
N ≥ 2  → 完整流程（七项结构）
```

**为什么重要**：七项结构的固定开销约 70 行，单图上结构占 85%。给一张图套完整流程，是浪费。

## 五个最容易出事的地方

| # | 情况 | 对策 |
|---|---|---|
| 1 | 局部替换（改一件衣服/一个物体） | 四段式：绝对不动 / 要替换 / 原位置处理 / 其余保留 |
| 2 | 画面里有中文 | 三选一：绕开 / 代码合成 / 正面复刻（给坐标字号色值） |
| 3 | 镜头短于 4 秒 | 先按 4–5 秒生成再裁。**补长优先冻帧，不慢放、不循环** |
| 4 | 声音字段空着 | `audio` 不填不许出卡片。不需要就写 `无` |
| 5 | 同一段连续动作 | 标同源，用同一条生成再剪 |

还有一类它专门查：**七类自相矛盾**（主体遮挡、文图冲突、时间卡点……）。见 `references/conflict-checks.md`。

## 文字策略：为什么会生成出字幕

`文字策略排查.md`。

最常见的三个原因，都在提示词里：

1. **台词和画面写在同一行** → 模型把台词也画出来
2. **「字幕」这个词出现了** → 模型对否定词处理很弱，提一次激活一次
3. **写了「保留品牌识别」** → 这是在要求画面出现文字

**修法：把台词剥离到音频段，删掉「字幕」二字，把「品牌识别」说成「招牌上的立体字」。**

详细对照和五步排查见 [文字策略排查](文字策略排查.md)。

## 去 AI 感（选配）

`references/anti-ai-look.md`。

**只有一条是硬性的：同一时空内的光影必须自洽。**

同一场景、同一时间段的连续镜头，光源方向、主光关系、色温、阴影方向必须一致。观众说不出哪里假，但会立刻觉得「这是拼的」。

其余按片型选配：

| 手法 | 商家单 | 理由 |
|---|---|---|
| 光影自洽 | ✅ 必须 | 不分片型 |
| 遮挡再露出 | ✅ 优先 | 门店门口天然有人流 |
| 手机对焦感 | ✅ 用 1–2 镜 | 手持感，像顾客自己拍的 |
| 前景短暂遮挡 | ⚠️ 慎用 | 15 秒片一闪就没了 |
| 24 帧运动模糊 | ⚠️ 看平台 | 很多入口不支持改帧率 |
| 微动态 | ❌ 不用 | 商家单节奏对不上 |

来源是外部创作者的 21 条拆解，**未在本项目实测**，按 `待核实` 处理。

## 这一环最值钱的东西：经验库

`references/lessons-log.md`。

它解决的是整个流程最大的问题——**0 条闭环，改进了也不知道有没有用**。

规则：

```
单次现象     → 待验证假设
同一条件复现 ≥2 次 → 已确认规律
```

每条必须写：平台/模型/入口、现象、改动、结果、适用范围。

**没有实际生成结果，不许写「有效」「已测试」。**

配套还有 `references/experiment-report-template.md`（单镜实验报告）——你回报实测结果时用它，它会把结果提炼成候选经验，你回一句「记」才入库。

**这是流程里唯一有学习机制的环节。** 其他环节错了就是错了，这一环能把错变成资产。

## 两个边界

**① H3 语法是专属的。** `references/h3-prompt-format.md` 只对 MiniMax H3 有效。用 Seedance、可灵、即梦，字段名全不对。其他平台用平台中立版。

**② 平台规格会过期。** `references/platform-profiles.md` 每条带核查日期，**超过 90 天视为 `待核实`**，不要凭记忆填规格。

目前已建档：可灵、即梦、Veo、Midjourney、豆包（Sora 已停用）。

## 证据标签（全流程统一）

这份 skill 定义了四个标签，建议整个仓库都用：

| 标签 | 含义 |
|---|---|
| `来源写明` | 用户/脚本直接写了，或 agent 亲自执行得到 |
| `材料推导` | 由材料推出的执行选择 |
| `待核实` | 尚未核实，冒号后写明核实什么 |
| `待补` | 缺素材或授权，不得暗示已提供 |

**这四个标签比「已完成/未完成」有用得多**——它区分了「抄的」「推的」「没验的」。

## 硬约束：参考图里的文字，必须一模一样

> **参考图上有字（店名、招牌、价签、菜单、资质），生成出来必须是那几个字，不许重绘、不许变形、不许换字。**
> **也不许推给后期。**

两条路，没有第三条：

| 路线 | 什么时候 | 怎么保证 |
|---|---|---|
| **原图直出** | 这一镜不用动 | 直接用客户原片，不生成 |
| **锁首帧保留** | 画面必须动 | 图生视频，首帧用原图，提示词写「该区域完全保留，不得重绘」 |

**验收**：生成结果和参考图**并排逐字对**。差一个字、错一个笔画 → 不合格，退回原图直出。

**做不到就换路线，不许打后期补丁**——后期贴回等于把问题藏起来，客户第一次看到成片時就会发现字被改过。

详见 [`references/on-image-text.md`](references/on-image-text.md)。

## 过关（九条，能勾）

进生成前逐条过。**不过关不许点生成。**

- [ ] 每镜有 `audio` 字段（不需要就明确写「无」）
- [ ] 四个高危点，占了的都有**具体对策**（不是「注意一下」）：
      中文文字 / 局部替换 / 短于 4 秒 / 同源连续动作
- [ ] 每镜只有**一个主要动作 + 一种镜头运动**
- [ ] 台词、屏幕文字、品牌文案**逐字**与来源一致
- [ ] 平台参数不确定的一律标 `待核实:具体项`（不凭记忆填）
- [ ] 没有「已测试」「有效」这类**未经验证**的说法
- [ ] 每镜末尾有一句**「这一镜的验收点」**
- [ ] 七类冲突排查过，每个冲突有**裁决句**（不留给模型二选一）
- [ ] **参考图带文字的区域**：走了原图直出或锁首帧保留，且没写「后期贴」

**前四条不达标不许生成；后五条不达标可以在卡里标注，但要写清。**

## 常见卡点

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 出来的人不像，四张脸都不像 | 把四视图**拼图**直接喂了 | 从拼图里裁单张正面特写，单独喂 |
| 屏幕上的字是乱码 | 让模型自己写中文 | **原图直出 / 锁首帧保留；不许后期贴** |
| 计划 2 秒，平台最短 4 秒 | 拿剪辑时码当模型参数 | **生成 4–5 秒再裁**，不改计划时长 |
| 一镜里人物做了三件事，崩了 | 一镜多任务 | 拆镜，一镜一动作 |
| 平台参数突然都错了 | 凭记忆填的 | 查入口页，写核查日期，超 90 天视为待核实 |
| 改了三处变好了，不知道哪处起作用 | 一次改太多 | 每轮只改一个变量 |
| 连续动作被拆成两条生成，接不上 | 没标同源 | 标 `same_take_group`，一条生成再剪 |
| 客户说"感觉不对" | 没有验收点 | 每镜写一句「这一镜的验收点」，对着判 |
