# 片子复盘

> 每条片子交付后填一次。**只填三行。**
> 攒到 20 条，我们才有"自己的判据"；在那之前，所有方法都是抄别人的。

---

## 三行

```
片子：<项目名 / 客户> ｜ 交付：YYYY-MM-DD

返工最久的一处：
当时怎么想的：
下次怎么防：
```

**填法说明（不是额外要填的内容）**

| 行 | 写什么 | 不要写什么 |
|---|---|---|
| 返工最久的一处 | 具体到哪一镜、哪一步，以及花了几轮 | "整体不太行" |
| 当时怎么想的 | 你当时的判断，哪怕后来证明是错的 | "按客户要求" |
| 下次怎么防 | 一条能写进流程的动作 | "下次注意" |

**判据：第三行必须能被别人执行。** 写成"注意钩子"没用；写成"钩子必须在需求确认阶段定，不留给分镜"才算。

---

## 可选：真踩了新坑才填

```
新症状：<看片时能看到的>
我猜的原因：
验证结果：<改完还在不在>
```

**"验证结果"只有三种：还在 / 没了 / 没试。** 写"应该是好了"等于没验证。

---

## 攒够之后怎么办

| 条数 | 该做什么 |
|---|---|
| 1–5 | 只记录，不改流程 |
| 6–10 | 同类问题出现 3 次以上 → 提一条候选 |
| 20+ | 能从复盘里反推出"我们的判断标准"，这时候才写进实战手册 |

**在此之前不要急着改手册**——单条经验写进手册，会把手册写成个人日记。
