## 开工先拨三个开关

不管你做什么片子，开工前把这三个拨一次：

| 开关 | 取值 | 怎么判 |
|---|---|---|
| **驱动方式** | 参数 / 叙事 | 观众会不会拿它和实物对比 |
| **生产规模** | 手搓 / 流程 | ≤8 镜手搓，≥9 镜上流程 |
| **风格浓度** | 信息流 / 叙事片 / 艺术片 | 把产品拿掉，这片子还成立吗 |

三个都拨完再动手。**拨错了返工最贵。**

- 详细说明 + 六种典型项目组合 → [`00-框架/三个开关.md`](00-框架/三个开关.md)
- 走流程的项目，四站怎么往深做 → [`00-框架/深度模式.md`](00-框架/深度模式.md)
- 拿到外部 skill 包，落我们哪一站 → [`00-框架/外部Skill落点.md`](00-框架/外部Skill落点.md)
- 分镜写完自己验收 → [`00-框架/每镜六问.md`](00-框架/每镜六问.md)

## 它解决什么问题

给商家做短视频，最容易死在这几处：

- 客户说「要高级感」，你不知道拍什么
- 素材收上来发现全是横屏带水印，不能用
- 分镜写好了，客户说「文案呢？他要说话啊」
- 提示词写完，生成出来手是六根手指
- 一条 30 秒的片子，改了 9 版

这套流程把每个环节的**输入、输出、过关标准**写死，让错误在便宜的时候被发现。

## 三个最重要的原则

**① 制作方式先于一切**

实拍 / 图生 / 纯 AI / 克隆，没定不许出素材清单。

依据：某驾校项目素材清单改了 4 版，根因是第 9 轮才说清「做的是图生视频 + 克隆形象」。

**② 一镜一任务，声音必填**

每个镜头只干一件事，并且必须写「这一镜听到什么」。

依据：两个项目被客户当场指出「只有画面提示词，没有声音提示词」。

**③ 越往后改越贵**

分镜改一个词 1 分钟，提示词改一句 5 分钟，生成了重跑 10 分钟加钱，剪完发现 2 小时。

所以每个环节结束前停一下，检查完再往下走。检查什么，见各节点目录。

## 目录

**01–05 是说明（靠人做），06–08 是 skill（靠工具做）。** 所以文件数差别很大：前者每环一份说明，后者是完整技能包。

```
00-框架/        流程全景、术语对照、已知卡点
01-流程/        按节点分目录，一个环节一份说明
02-模板/        可直接填的空表
03-话术/        可直接复制给客户的文本
04-案例/        真实项目（已脱敏）
05-学生包/      打包发给新人的版本
06-问题/        使用中遇到的问题
07-实战手册/    出问题时查的几份手册（不是流程步骤）
08-导演思维/    四课训练：学生最缺的是"为什么这么拍"
```

## 每个人的用法

**自己接单**：从 `01-流程/01` 开始，按节点走，用 `02-模板` 里的表。

**带新人**：把 `05-学生包/` 整个发给他，让他先跑一遍模拟项目，再上真实客户。

**学生片子"不难看但不好看"**：那不是流程问题，是导演思维没长出来 → `08-导演思维/`，四课都是练习，不是阅读。

**发现问题**：记到 `06-问题/` 里，六行就够（见 [`06-问题/模板.md`](06-问题/模板.md)）。不要先想解决方案，先记卡在哪。

## 贡献

- **想改东西**：先看 [GOOD-FIRST-TASKS.md](GOOD-FIRST-TASKS.md)，挑一个认领
- **提问题**：直接在 `06-问题/` 新建文件，或用 Issue
- **提方案**：fork 一份改，提 PR
- **不要直接改主分支**——母版只有一份，多人同时改会散

改动门槛：**同一个问题被 3 个人遇到，才改母版**。1 个人遇到只记录。
