# 上下游术语与交付物对照表 v0.1

> 用途：学生先上基础课（镜头语言 + 镜头包），再转到商用课（客户交付）。两份材料各有一套词，学生混用会直接做错事。
> 这份表给三类人看：**老师**（确认我没曲解他的体系）、**学生**（转段时对照）、**你自己**（出题和验收时对齐口径）。
> 依据：`AI视频基础·全三册`、`AI视频设计与生成准备·团队上手`、`AI视频生产工作流·图解授课版`（36页）三份原始材料，逐节核对，非推测。

---

## 一、总原则：三段关系，只有三种

| 关系 | 含义 | 处理方式 |
|---|---|---|
| **等价** | 同一个东西，两个名字 | 统一用上游说法，下游文档不再另起名 |
| **上下游** | 他的产出是我的输入 | 保留两份，中间加一道转换 |
| **单边独有** | 只有一方有 | 不做映射，直接吸收或补课 |

**不存在"两套并行"的第四种关系。** 凡是看起来像"两套做法"的，都落在这三类里。

## 二、主对照表

### A. 等价（共 5 组，统一用左列说法）

| # | 上游说法（老师） | 下游说法（你） | 统一用 |
|---|---|---|---|
| A1 | 节奏节点 Beat | 分镜段落 / 场次 | **节奏节点** |
| A2 | 连续性（继承什么、易错什么） | 跨镜一致性 | **连续性检查** |
| A3 | 版本记录（只改一个变量） | 实验记录 | **生成记录** |
| A4 | 静帧预演 | （无） | **静帧预演** |
| A5 | 一镜一任务 | 单镜单运动 | **一镜一任务** |

### B. 上下游（共 5 组，必须两道工序）

| # | 上游产出 | 下游接过来做什么 | 缺什么、谁补 |
|---|---|---|---|
| B1 | **需求卡**（观众 / 看完留下什么 / 主要事件 / 表达方式 / 时长画幅 / 不能改变 / 资源 / 待确认） | 转成**一表通**：补制作方式、素材形态、授权、谁拍板、报价影响 | 上游定"要什么感觉"，下游定"怎么做得起"。**下游必须补，不能直接拿需求卡给客户填** |
| B2 | **视听脚本**（时段 / 画面发生什么 / 声音做什么 / 镜号） | 并进**分镜表**，加 `素材序号` 和 `口播` 两列 | 上游有声音列，下游有素材列。**合成一张六列表** |
| B3 | **镜头卡**（任务 / 开始 / 变化 / 结束 / 机位 / 构图 / 光线 / 参考 / 声音 / 验收） | 编译成**单镜提示词** + 平台参数 | 上游写"要什么"，下游写"怎么跟模型说" + 时长档位、参考图上传顺序 |
| B4 | **共用参考**（人物 / 场景 / 道具 / 干净画面 / 机位图） | 变成**素材清单**的采集项 + 采集 SOP | 上游假设参考图已有；下游负责让客户拍出来、催回来、验合规 |
| B5 | **生成计划**（先试风险镜 / 三人分工 / 记录方式） | 变成**生成任务包**：秒数、上传顺序、完整提示词、音频要求、次数与费用记录 | 上游管顺序，下游管每次生成的账 |

### C. 单边独有 —— 上游有、你必须吸收（7 项）

这几项在你的 15 节点流程里是空的，学生来了默认会，你要认下来并写进下游标准件：

| # | 上游资产 | 现在下游的状态 | 什么时候用 |
|---|---|---|---|
| C1 | **三帧法**（第一帧 / 转折帧 / 最后一帧） | 无 | 客户只给一句"要高级感"时，先用三帧把方向钉死 |
| C2 | **感觉→证据六要素**（动作 / 环境 / 距离 / 光线 / 声音 / 镜头） | 无 | 把"孤独/紧张/高级"翻译成能拍的句子 |
| C3 | **去掉形容词检查** | 无 | 提示词写完自查：删掉形容词还讲得通吗 |
| C4 | **静帧预演** | 无 | 分镜定稿后、生成前，成本最低的故事验证 |
| C5 | **连续性检查表**（S01→S02 继承什么 / 易错什么） | 只有"跨镜一致"一句 | 多镜同场景项目，生成前必过 |
| C6 | **单镜验收 8 项**（身份 / 主动作 / 摄影机 / 物理关系 / 接续 / 时长 / 声音 / 可用程度） | 节点 14（现未编号，见 10-后续环节）只有三分支，无清单 | 每镜生成后必查 |
| C7 | **风险镜先行**（先试最容易崩的镜） | 无 | 生成排期第一步，不要从 S01 顺序做 |

### D. 单边独有 —— 下游有、上游没有（6 项，你的课的主体）

| # | 下游资产 | 上游的空白 | 为什么商用必须有 |
|---|---|---|---|
| D1 | **制作方式判定**（实拍 / 图生 / 纯 AI / 克隆） | 上游默认"方法自选" | 制作方式决定素材形态，某驾校 4 版返工的根因就是没先定 |
| D2 | **素材清单**（规格六要素 / ★ 开工包 / 回收表） | 上游没有清单概念 | 客户不知道拍什么就拍废 |
| D3 | **采集 SOP**（数字人 / 声音 / 实景 / 屏幕） | 上游假设参考图已有 | 真实项目一半时间在这 |
| D4 | **授权三档 + 合规禁语** | 上游没有 | 商用投放的法律底线 |
| D5 | **催收回收**（六段话术 + 三天降门槛） | 上游不需要 | 清单发出去不是结束 |
| D6 | **平台真实约束**（≥4s / ≤12s / 冻帧补长 / 中文文字三策） | 上游只写"按工具档位适配" | 违反就报错或画面崩 |

## 三、六个学生一定会犯的混用错误

这六条是转段时最贵的坑，上课第一天就要讲：

| # | 学生会怎么做 | 为什么错 | 正确做法 |
|---|---|---|---|
| 1 | 把**需求卡**直接发给客户填 | 客户看不懂"看完留下什么"，也填不出"不能改变什么" | 需求卡是对内文档；对客户发**一表通**（判断行让他划掉） |
| 2 | 用**视听脚本**直接生成 | 少了素材序号，不知道每个镜头要客户拍什么 | 先过一道"素材映射"，没有素材的镜头标红 |
| 3 | 用**计划时长**当平台时长 | 上游写"3 秒"，平台最短 4 秒，生成必失败或裁掉动作 | 计划时长 ≠ 生成时长；生成留余量再裁 |
| 4 | 拿**自己的审美**当验收 | 上游 8 项是技术验收，客户验收是"能不能发" | 两层验收：先单镜 9 项（8 基础 + 可交付性），再整片商用 5 项 |
| 5 | 拿**共用参考图**当已有素材 | 上游案例里参考图是备好的，真实项目要自己采 | 参考图是采集产物，进素材清单，走采集 SOP |
| 6 | 把**镜头卡**当提示词用 | 镜头卡是给人看的，模型读不懂"任务：让输入停止可见" | 镜头卡 → 编译成提示词（七问：有什么/谁在做什么/机位/环境/光线/节奏/声音） |

## 四、交付物接口：他在哪一步交，我在哪一步接

```
基础课                          你的课
─────────────────────────────────────────────────────────
需求卡          ──────────────►  转一表通（补制作方式/授权/报价影响）
                                  ＋ 出素材清单
                     ↑ 客户在这里第一次出现
三帧 + 六要素   ──────────────►  写进项目简报，作为提示词的"证据链"依据
成片说明 Spec   ──────────────►  直接当项目简报用（不改）
视听脚本        ──────────────►  并成六列分镜表（加素材序号 / 口播）
镜头卡          ──────────────►  编译成提示词 + 平台参数
共用参考        ──────────────►  展开成素材清单采集项 → 客户实采 → 回收入库
静帧预演        ──────────────►  原样用（成本最低的质量关口）
生成计划        ──────────────►  风险镜先行 → 生成任务包 → 逐次记账
单镜验收 8 项   ──────────────►  原样用，加"可交付性"一栏
                                  ＋ 整片验收（客户视角）
                                  ＋ 交付包清点
```

**关键一句**：老师那边交的是**镜头包**（给执行者看的）；你这边交的是**交付包**（给客户看的）。镜头包是交付包的一部分，不是替代关系。

## 五、术语速查（学生贴墙版）

| 他说 | 我说 | 一句话区别 |
|---|---|---|
| 需求卡 | 一表通 | 他要什么感觉 / 客户给什么条件 |
| 成片说明 | 项目简报 | 同一份，直接沿用 |
| 视听脚本 | 分镜表 | 他管顺序和声音 / 我加素材和口播 |
| 镜头卡 | 提示词 | 给人看的 / 给模型看的 |
| 共用参考 | 素材清单 | 假设有 / 负责采 |
| 生成计划 | 生成任务包 | 排顺序 / 管每次的账 |
| 单镜验收 | 技术验收 | 镜头对不对 / 片子能不能发 |

## 六、这份表还没解决的三件事

1. **术语统一到什么程度**：现在建议"等价项用上游说法"，但这会让你的 `client-brief` 里出现"节奏节点"这种上游词，需要改 skill 文案。
2. **六列分镜表的最终列序**：上游是「时段/画面/声音/镜号」，下游是「镜号/时长/画面/口播/素材序号」，合并后列序未定。
3. **你那份 15 节点手册要不要改口径**：如果要和上游术语对齐，节点 7（现 09 提示词编译）的"分镜与提示词"应拆成"视听脚本 → 镜头卡 → 提示词"三步，与老师的粒度一致。

这三件要你定，我不擅自改已发布的手册。
