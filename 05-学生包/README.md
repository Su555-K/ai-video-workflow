# 学生工具包 · 说明与流程对照

> ⚠️ **本包的步骤编号是旧版 `0–7`，和现行 `01-流程` 的 `01–10` 不是一套。** 对照：
>
> | 本包 | 现行 | | 本包 | 现行 |
> |---|---|---|---|---|
> | 0 需求换源 | 01 需求确认 | | 4 图片与音频资产 | 05 身份资产 |
> | 1 素材清单 | 02 素材清单 | | 5 生成 | 10 后续环节 |
> | 2 采集与回收 | 03 + 04 | | 6 验收 | 10 后续环节 |
> | 3 视听脚本→镜头卡 | 07 脚本改造 | | 7 剪辑与交付 | 10 后续环节 |
>
> **本包没有 06 参考拆解、08 客户确认两环。** 要按主线走看 `01-流程/`，本包只当发给新人的简表。

> ⚠️ **六列结构暂定**：先跑一个真实项目再定列数。固定的是「每镜必须回答的 6 个问题」，不是列的排法。改列不影响下游，只要 6 个问题还在。

> 这不是教程，是**干活时对着看的一张表**。教程在基础课那边，这里只解决三件事：
> 这一步的重点是什么、上一步给我什么、我能用什么工具做。
>
> **最重要的一条：本工具包不绑定任何软件。** 全组用 WorkBuddy、DeepSeek、MiniMax、豆包、剪映、还是别的，都按同一套流程走。判断标准是"产出物达标没"，不是"你用了哪个工具"。

> **第一次用？先看 [安装与开始](安装与开始.md)**（装 skill + 验证 + 第一次跑什么）。

## 一、流程的五个重点（其余都是细节）

| # | 重点 | 一句话 | 违反的代价 |
|---|---|---|---|
| 1 | **制作方式先于一切** | 实拍/图生/纯AI/克隆没定，不许出素材清单 | 某驾校素材清单改 4 版，全部作废 |
| 2 | **一镜一任务 + 声音必填** | 每个镜头只干一件事，且必须写"这一镜听到什么" | 某甜品店、某餐饮招商项目都被客户当场指出"只有画面没有声音" |
| 3 | **静帧预演在生成之前** | 用分镜图按时长排一遍，先看顺序和停顿 | 直接生成 → 发现节奏不对 → 全部重抽 |
| 4 | **单镜验收过了才进粗剪** | 9 项打勾，不合格退回该镜，不带病往下 | 整片剪完才发现第 3 镜不能用 |
| 5 | **交付包不等于成片** | 授权、回收表、生成记录、交付说明，少一样都可能返工 | 客户自己改价格、自己乱发 |

**这五条之外，都是可以商量的操作细节。这五条不让步。**

## 二、各环节：接什么 → 做什么 → 交什么 → 用什么

> "上一步给我什么"这一列是重点。**接不到东西就停下问，不要自己编。**

### 0 需求换源（新客户进来第一步）

| | |
|---|---|
| 上一步给我什么 | 客户的微信原话、品牌资料、对标视频（有什么算什么）；基础课学的需求卡**不能直接给客户** |
| 这一步做什么 | ① 判制作方式（四问：有现成素材吗/要出人吗/客户能拍吗/多长）② 列事实分三档（原话/资料/反推）③ 能推的写成判断行让客户划掉 ④ 只留 ≤3 个真问题 |
| 这一步交什么 | **一表通**（对外，客户填）+ **推导册**（对内，不外发） |
| 过关 | 对外版没有一句"为什么问"、没有日期承诺、没有推导过程 |
| 需要什么能力 | 把散乱信息整理成结构化表格；能导出 DOCX/在线文档 |
| 可用工具 | WorkBuddy 的「需求确认及素材」skill；没有 skill 就用模板手填；DeepSeek/其他模型可以帮你梳理，但**判断行必须你自己下** |
| 常见卡点 | 把需求卡的"观众看完留下什么"写进一表通 → 客户看不懂。**客户只回答"是什么"，不回答"为什么"** |

### 1 素材清单

| | |
|---|---|
| 上一步给我什么 | 定稿的一表通（含制作方式） |
| 这一步做什么 | 按七章模板填；每项写死规格六要素（画幅/分辨率帧率/单段时长/机位运镜/光线时段/留白禁项）；高优先级 ≤10 项；★ 只给 5–8 项开工必需 |
| 这一步交什么 | 素材采集清单（含分镜对照、回收表、合规项） |
| 过关 | 没有"高清""一些""随便拍点"；每项都能被客户拿手机照着拍 |
| 需要什么能力 | 出可打印/可转发的文档；能按客户条件裁剪要求 |
| 可用工具 | 任何文档工具；WorkBuddy 的 client-brief 可以自动出；没有就填模板 |
| 常见卡点 | 要求写得像摄影指导（4K/布光）→ 客户是店主，做不到。**门槛往下降：照片能解决不要求视频** |

### 2 采集与回收

| | |
|---|---|
| 上一步给我什么 | 已发出的素材清单 |
| 这一步做什么 | ① 把采集 SOP 对应章节整段发客户 ② 优先启动数字人+声音（20 分钟，但条件不满足要重拍）③ 三天不齐就按 ★ 包先排剪辑 ④ 缺件按话术处理 |
| 这一步交什么 | 客户拍回的原片 + 回收表（已交/待拍/**无法拍**） |
| 过关 | "无法拍"栏有内容；数字人是视频不是截图；声音 60 字 13 秒 3 遍 |
| 需要什么能力 | 能发文档、能催、能判断素材能不能用 |
| 可用工具 | 微信/企业微信 + 回收表；**这一步不需要 AI** |
| 常见卡点 | 学生在等齐才开工 → 拖三天。**正确做法：★ 项到了就出粗剪** |

### 3 视听脚本 → 镜头卡（相当于基础课的"镜头包"）

| | |
|---|---|
| 上一步给我什么 | 客户确认的素材 + 定稿的文案/口播 |
| 这一步做什么 | ① 先算时长：按「音节 ÷ 语速 + 停顿」估，**不是字数÷4.5**（工具见 `01-流程/07-脚本改造/scripts/calc_pace.py`）② 排节奏节点（5 个左右）③ 拆镜头（一镜一任务）④ 每镜写：时段/画面/声音/结束状态 ⑤ 标素材序号 |
| 这一步交什么 | **六列分镜表**（镜号/时段/画面/声音/口播/素材） |
| 过关 | 每镜都有声音列且写了内容；每镜都能指到具体素材；时长能对上 |
| 需要什么能力 | 文案拆解 + 时长核算 |
| 可用工具 | WorkBuddy 的「Seedance 分镜脚本」可出三格式；其他模型可以帮你拆，但**时长必须自己算** |
| 常见卡点 | 客户说"做 30 秒"就直接拆 30 秒 → 实际文案 83 秒。**412 字标 58 秒 = 7.1 字/秒，不可能** |

### 4 图片与音频资产

| | |
|---|---|
| 上一步给我什么 | 分镜表 + 客户素材 |
| 这一步做什么 | ① 人物：同一人正面/侧面/背面，**四视图拼图不能直接喂模型**（会平均四张脸）② 场景/道具：能反复入画的才建档 ③ 画面里的中文：字号小、多行、UI 一律**不要让模型生成** ④ 音频：需要干净人声先分离，再处理 |
| 这一步交什么 | 干净参考图（每镜一张）+ 人声/环境/音效分轨 |
| 过关 | 中文逐字正确；同一人物是同一张脸；音轨能单独替换 |
| 需要什么能力 | 图生图/局部改；能画字（任何能做图文的工具都行）；音频分离/变调 |
| 可用工具 | 任意图像生成/编辑工具 + 任意能做排版出图的工具（HTML 截图也行）；音频用任意带分离功能的工具 |
| 常见卡点 | 让模型生成手机屏幕文字 → 出现乱码。**边界：要出现的字必须原样——用原图直出或锁首帧保留，不许重绘，也不许推给后期** |

### 5 生成

| | |
|---|---|
| 上一步给我什么 | 分镜表 + 参考图 + 每镜提示词 |
| 这一步做什么 | ① **先试最容易崩的镜**（手部接触、快速运动、多人、文字、拉远轨迹），不要从 S01 顺序做 ② 每镜只改一个变量 ③ 记下模型/参数/次数/费用 |
| 这一步交什么 | 每镜 2–3 个候选 + 生成记录 |
| 过关 | 每条都有记录；能用一句话说清"这条为什么不行" |
| 需要什么能力 | 能提交生成任务、能拿回成片 |
| 可用工具 | **不固定**：Seedance / MiniMax / 可灵 / Runway / 即梦 / 豆包，用你手上有额度的那家 |
| 常见卡点 | ① 时长不匹配：计划 2 秒，平台最短 4 秒 → **生成 4-5 秒再裁**，不要放慢或循环 ② 不满意就无限重抽 → **每次只改一个变量** |

### 6 验收（两层，缺一层不算过）

| | |
|---|---|
| 上一步给我什么 | 每镜候选片段 |
| 这一步做什么 | **第一层 单镜 9 项**（8 项基础 + 1 项可交付性）：身份/主动作/摄影机/物理关系/接续/时长/声音/可用程度/可交付性 → 处置四分支：可用 / 重做这一镜 / 局部修补 / 待复核<br>**第二层 整片 5 项**：叙事讲得通吗 / 字幕遮主体吗 / 音量稳吗 / 合规吗（过期价格、绝对化用语、无授权肖像）/ 光影连贯吗 |
| 这一步交什么 | 验收单（逐镜打勾+处置） |
| 过关 | 每个"退回"都写得清是哪一项不合格，不是"感觉不对" |
| 需要什么能力 | 会看片 + 会填表 |
| 可用工具 | 验收单模板（见 `模板/单镜验收单.md`） |
| 常见卡点 | 用自己的审美验收。**先看镜头有没有完成它的任务，再看好不好看** |

### 7 剪辑与交付

| | |
|---|---|
| 上一步给我什么 | 通过验收的片段 + 分轨声音 + 字幕文本 |
| 这一步做什么 | ① 静帧/粗剪先看故事顺不顺 ② 字幕按**最终音轨**重校，不是按脚本 ③ 交付包逐项勾 |
| 这一步交什么 | 成片 + 交付包（见 `模板/交付包清单.md`） |
| 过关 | 字幕与音轨逐句对齐；交付包清单全勾 |
| 需要什么能力 | 能剪、能导出指定规格 |
| 可用工具 | **不固定**：剪映、Premiere、达芬奇、CapCut，只要能导出竖屏 1080×1920/30fps |
| 常见卡点 | 字幕按脚本校 → 对不上嘴。**必须用实际音轨** |

## 三、工具怎么选：先看能力，再看软件

同一件事有多个工具能做，按这条规则选，不要纠结品牌：

| 你要的能力 | 判断标准（不看品牌） | 举例（不代表都支持，按你手上有的选） |
|---|---|---|
| 文生视频 | 能给 4–12 秒、能接受参考图 | Seedance / MiniMax / 可灵 / 即梦 |
| 图生视频 | 能锁首帧、动作可控 | 同上，多数都支持 |
| 人物一致性 | 支持角色/参考图 | 看平台是否给"角色参考"入口 |
| 中文画面 | 大字号印刷体能出对，UI 不能 | 任何图生模型都别指望小字 |
| 人声分离 | 能分出人声轨 | 任意带分离功能的工具 |
| 变调不变速 | 音高变、时长不变 | 任意音频工具；没有就换思路 |
| 剪辑字幕 | 能导出 9:16 1080×1920 | 剪映/达芬奇/CapCut |

**一句话规则**：能力对得上、结果能验收，就用它。**不要因为教程写了某个软件就去装它。**

---

## 四、三条纪律（比任何技巧都重要）

1. **接不到上一步的产出，就停下问。** 不要自己编客户需求，不要假设素材已有。
2. **一镜一任务，声音必填。** 声音那一列空着，就等于这一镜没想清楚。
3. **每次只改一个变量，并记录。** 改了三个地方变好了，你不知道是哪个起的作用。

### 六列分镜表 vs 干净分镜表

这两个不是替代关系，是两个阶段：

```
六列分镜表（想清楚）  →  干净分镜表（交出去）
  台词和画面在一张表      台词和画面分成两张表
  自己用                  给模型和配音用
```

**为什么必须过渡一次**：六列表里台词和画面在同一行，直接喂给视频模型，它会把台词也「画」出来——这是生成出字幕的头号原因。详见 `../01-流程/09-提示词编译/文字策略排查.md`。
